# ADR 0002 · 不合并进程

- 日期：2026-10-23
- 状态：**已采纳**

## 背景

「web 从同一个入口进入」有三种实现层次：
① nginx 层统一路由（三个进程）② 应用层统一网关（一个进程反向代理）③ 合成一个进程。

## 决策

**保持 8010（CPT）/ 8098（emotion 看板）/ 8091（lab）三个独立进程，
入口统一由 nginx + Emotion-CPT 的门面承担。**

## 理由

1. **emotion-core 的整套降级设计建立在「CPT 可能挂」这个前提上。**
   `cpt_client.py` 的 4 条硬要求里，第 2 条就是"绝不抛"、第 5 条是"不走 nginx"，
   并有 `basis="pct_fallback"` 的百分比兜底。合成一进程后，这个前提消失，
   盘中 pipeline 崩一次就会带走看板，而降级路径变成死代码。
2. **SLA 不对齐**：CPT 是实时轮询（`--poll-seconds 30`），emotion 是日更批处理。
   合成一个进程意味着两种负载共享一份故障域。
3. **入口统一 ≠ 进程统一**。nginx 已经承担了 TLS、auth_basic、插件门卫依赖的
   Host/Origin 改写 —— 在应用层重做一遍只会多出一套不一致的规则。

## 代价

- 跨进程仍有一次 HTTP 往返（3s 超时）—— 后续可由 P2/P3 的共用件把这条路径消掉
- 部署上仍是三个 unit 套件 —— 但真相源可以收成一个（见 ADR 0003 的延伸）
