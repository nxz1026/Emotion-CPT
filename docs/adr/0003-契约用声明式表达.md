# ADR 0003 · 契约用声明式表达

- 日期：2026-10-23
- 状态：**已采纳**

## 背景

跨仓契约此前有三种表达：markdown 表格、手抄的 SQL 片段、手抄的常量。
它们都能漂移，且漂移时**没有任何东西会红**。

## 决策

**契约用声明式 dataclass 表达，且字段名、单位、语义都是契约本体的一部分。**

```python
Column("bid1_lots", "double precision", True,
       unit="手（1 手 = 100 股）",
       semantics="买一挂单量；读方阈值用股时必须 ×100")
```

## 理由

1. **最贵的漂移不是字段名，是同名不同义**。`bid1_lots` 是「手」不是「股」；
   `distance_pct` 是**百分数**不是小数。这两个坑一旦踩中，
   算出来的价会**看起来合理但完全错误**（上游曾把 1258 当成 8886）。
   把 `unit` / `semantics` 写进契约本体，门禁才查得出"读方用错了单位"。
2. **声明式可被机器读**：门禁能解析、探针能产出指纹、上游能自动比对。
   手写 SQL 字符串做不到。
3. **不可变**（frozen dataclass）⇒ 契约不会被就地改写，指纹才有意义。

## 代价

- 声明式 DSL 要能表达真实 DDL 的全部信息，复杂迁移仍需保留 SQL 文件
  ⇒ 本仓的 `schema/migrations/` 存 SQL，`contracts/` 存结构化声明，两者并存
